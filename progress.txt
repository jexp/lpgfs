## Task 014: Integrate cache with database queries
- **Status:** Completed
- **PRD Reference:** Section 12.4 (Caching)

### Key Decisions
- Added optional `cache?: Cache` parameter to all query functions
- Cache is checked before executing database queries (cache-aside pattern)
- Results are stored in cache after successful database queries
- TTL is automatically determined by the cache based on key prefix:
  - `getLabels()` → labels (60s)
  - `getNodesByLabel()` → nodes (30s)

  - `getRelationshipProperties()` → props (10s)
- Cache parameter is optional - functions work without cache for backward compatibility
- Empty results are also cached to avoid repeated queries for non-existent data
- Null results (not found) are cached for relationship properties

  3. Register FUSE handlers by creating `FuseOps` object mapping to our handlers
  4. Mount filesystem at specified path using fuse-native

  - All write operations return EROFS

- `unmount()` function uses `fusermount -u` (Linux) or `umount` (macOS)
- Daemon states: 'stopped' | 'starting' | 'running' | 'stopping'
